1. Pendahuluan

Dalam pengembangan perangkat lunak, perubahan terhadap kode program terjadi secara terus-menerus. Programmer dapat menambahkan fitur, memperbaiki kesalahan, mengubah struktur kode, atau menghapus bagian tertentu. Tanpa mekanisme pengelolaan perubahan yang baik, riwayat pekerjaan akan sulit dilacak dan kesalahan dapat sulit dipulihkan. Oleh karena itu, diperlukan Version Control System (VCS).

2. Pengertian Version Control

Version Control adalah sistem yang digunakan untuk mencatat, mengelola, dan melacak perubahan pada file dari waktu ke waktu. Version Control memungkinkan pengguna mengetahui perubahan yang dilakukan, melihat riwayat pekerjaan, membandingkan versi, serta kembali ke kondisi sebelumnya apabila diperlukan.

Dalam proyek perangkat lunak, Version Control juga membantu beberapa pengembang bekerja pada proyek yang sama secara lebih terorganisasi. Setiap perubahan dapat disimpan sebagai versi atau commit sehingga perkembangan proyek dapat ditelusuri.

3. Fungsi Version Control

  • Melacak perubahan file dan kode program.
  • Menyimpan riwayat perubahan sehingga perkembangan proyek dapat ditelusuri.
  • Memungkinkan pemulihan atau pemeriksaan versi sebelumnya ketika terjadi kesalahan.
  • Mendukung pengembangan secara kolaboratif oleh beberapa pengguna.
  • Memisahkan pengembangan fitur menggunakan branch.
  • Membantu membandingkan perubahan antara satu versi dan versi lainnya.

4. Jenis-Jenis Version Control

4.1 Local Version Control

Local Version Control menyimpan riwayat perubahan pada komputer lokal. Sistem ini dapat membantu mengelola beberapa versi file, tetapi kemampuan kolaborasinya terbatas karena repositori tidak secara langsung digunakan bersama oleh banyak pengguna.

4.2 Centralized Version Control

Centralized Version Control menggunakan satu server pusat sebagai tempat penyimpanan utama repositori. Pengguna mengambil dan mengirim perubahan melalui server tersebut. Contoh sistem yang termasuk kategori ini adalah Subversion (SVN) dan CVS.

4.3 Distributed Version Control

Distributed Version Control memungkinkan setiap pengguna memiliki salinan repositori beserta riwayat perubahannya. Git merupakan salah satu contoh Distributed Version Control System (DVCS).

5. Git sebagai Version Control

Git adalah sistem Version Control terdistribusi yang digunakan untuk mengelola dan melacak perubahan pada proyek, terutama proyek perangkat lunak. Git dapat digunakan secara lokal dan dapat dihubungkan dengan layanan penyimpanan repositori jarak jauh seperti GitHub.

6. Konsep Dasar Git

6.1 Working Directory

Working Directory adalah folder proyek tempat pengguna membuat, mengubah, atau menghapus file. Perubahan yang dilakukan pada tahap ini belum otomatis menjadi bagian dari commit.

6.2 Staging Area

Staging Area adalah area sementara untuk menentukan perubahan mana yang akan dimasukkan ke dalam commit. Perubahan dapat dimasukkan ke staging menggunakan perintah git add.

6.3 Local Repository

Local Repository adalah repositori Git yang berada pada komputer pengguna. Commit yang dibuat tersimpan di dalam repositori ini beserta informasi riwayat perubahan.

6.4 Remote Repository

Remote Repository adalah repositori yang berada pada lokasi lain, biasanya server atau layanan daring. GitHub dapat digunakan sebagai remote repository untuk menyimpan dan berbagi repositori Git.

7. Alur Dasar Version Control dengan Git

Alur dasar pengelolaan perubahan menggunakan Git adalah sebagai berikut:

Working Directory
    |
  git add
    v
Staging Area
    |
  git commit
    v
Local Repository
    |
  git push
    v
Remote Repository

Apabila perubahan dari remote repository perlu diambil ke komputer lokal, perintah git pull dapat digunakan.

Remote Repository
    |
  git pull
    v
Local Repository

8. Praktik Dasar Version Control Menggunakan Git

Bagian berikut menunjukkan praktik sederhana menggunakan Git pada sebuah proyek bernama PMW. Contoh ini menggunakan file Tugas1.html dan diasumsikan Git Bash telah tersedia pada komputer.

8.1 Membuka Folder Proyek

Masuk ke folder proyek melalui Git Bash. Contoh:

cd ~/Documents/Kuliah/PMW

Periksa lokasi saat ini:

pwd

Periksa isi folder:

ls

8.2 Membuat Repository Git

Jika folder proyek belum menjadi repository Git, jalankan:

git init

Perintah tersebut membuat folder .git yang berisi informasi yang diperlukan oleh Git. Repository sebaiknya dibuat pada folder proyek yang memang ingin dikelola agar file dari folder lain tidak ikut tercatat.

8.3 Memeriksa Status Repository

git status

Perintah git status digunakan untuk melihat kondisi repository, termasuk file yang belum dilacak, file yang berubah, dan file yang telah dimasukkan ke staging area.

8.4 Memasukkan File ke Staging Area

Jika hanya file Tugas1.html yang ingin dimasukkan ke commit:

git add Tugas1.html

Perintah tersebut hanya memasukkan file yang disebutkan. Untuk memasukkan seluruh perubahan yang tersedia pada folder proyek, dapat digunakan:

git add .

Penggunaan git add . perlu diperhatikan karena seluruh perubahan yang terjangkau oleh perintah tersebut dapat masuk ke staging area.

8.5 Membuat Commit

Setelah file berada di staging area, buat commit:

git commit -m "Menambahkan Tugas 1"

Commit merupakan titik riwayat yang menyimpan perubahan yang telah dipilih. Pesan commit sebaiknya singkat tetapi menjelaskan perubahan yang dilakukan.

8.6 Melihat Riwayat Commit

git log --oneline

Perintah tersebut menampilkan riwayat commit dalam bentuk ringkas. Setiap commit memiliki identitas atau hash yang dapat digunakan untuk mengidentifikasi perubahan.

9. Praktik Branch

Branch digunakan untuk membuat jalur pengembangan yang terpisah. Dengan branch, pengguna dapat mengembangkan fitur tertentu tanpa langsung mengubah branch utama.

9.1 Membuat dan Berpindah ke Branch

git switch -c fitur-baru

Perintah tersebut membuat branch bernama fitur-baru sekaligus berpindah ke branch tersebut.

9.2 Melihat Branch

git branch

Tanda bintang (*) menunjukkan branch yang sedang aktif.

9.3 Berpindah Kembali ke Main

git switch main

9.4 Menggabungkan Branch

Setelah pekerjaan pada branch fitur-baru selesai dan telah di-commit, perubahan dapat digabungkan ke main:

git switch main
git merge fitur-baru

Apabila Git menemukan perubahan yang saling bertentangan pada bagian yang sama dan tidak dapat menentukan perubahan yang harus digunakan secara otomatis, dapat terjadi merge conflict. Konflik tersebut perlu diselesaikan secara manual sebelum proses merge dapat diselesaikan.

10. Menghubungkan Repository Lokal dengan GitHub

Untuk menyimpan repository Git secara daring, repository lokal dapat dihubungkan dengan repository GitHub. Buat repository kosong di GitHub, kemudian tambahkan alamatnya sebagai remote.

git remote add origin https://github.com/username/nama-repository.git

Periksa remote yang telah terdaftar:

git remote -v

11. Push ke Remote Repository

Push digunakan untuk mengirim commit dari repository lokal ke remote repository.

git push -u origin main

Setelah hubungan tracking antara branch lokal dan remote telah ditetapkan, push berikutnya pada branch tersebut biasanya dapat dilakukan dengan:

git push

12. Pull dari Remote Repository

Pull digunakan untuk mengambil perubahan dari remote repository dan mengintegrasikannya ke branch lokal yang sedang digunakan.

git pull

13. Contoh Praktik Lengkap

Berikut contoh alur dari pembuatan repository hingga pengiriman perubahan ke GitHub:

  1. Masuk ke folder proyek.
  2. Membuat repository Git dengan git init jika repository belum tersedia.
  3. Memeriksa status menggunakan git status.
  4. Memasukkan file yang diperlukan ke staging menggunakan git add.
  5. Membuat commit menggunakan git commit.
  6. Membuat repository di GitHub.
  7. Menghubungkan repository lokal dengan GitHub menggunakan git remote add origin.
  8. Mengirim commit ke GitHub menggunakan git push.
cd ~/Documents/Kuliah/PMW
git init
git status
git add Tugas1.html
git commit -m "Menambahkan Tugas 1"
git remote add origin https://github.com/username/PMW.git
git push -u origin main

14. Praktik Perubahan Berikutnya

Jika file Tugas1.html kemudian diubah, perubahan tersebut dapat disimpan sebagai commit baru.

git status
git add Tugas1.html
git commit -m "Memperbarui Tugas 1"
git push

16. Hal yang Perlu Diperhatikan Saat Praktik

  • Pastikan terminal berada pada folder repository yang benar sebelum menjalankan perintah Git.
  • Gunakan git status secara berkala untuk mengetahui kondisi repository.
  • Gunakan git add <nama_file> jika hanya file tertentu yang ingin dimasukkan ke commit.
  • Hindari penggunaan git add . secara sembarangan apabila terdapat file yang tidak ingin dimasukkan ke repository.
  • Buat pesan commit yang menjelaskan perubahan secara jelas.
  • Pastikan branch yang aktif sudah benar sebelum melakukan commit, merge, atau push.
  • Jangan menggunakan git push --force tanpa memahami dampaknya karena perintah tersebut dapat menimpa riwayat pada remote repository.
  • Simpan file yang tidak diperlukan dalam repository menggunakan .gitignore apabila sesuai dengan kebutuhan proyek.

17. Kesimpulan

Version Control merupakan mekanisme untuk mengelola, mencatat, dan melacak perubahan pada proyek. Sistem ini penting dalam pengembangan perangkat lunak karena membantu menjaga riwayat perubahan, memulihkan kondisi sebelumnya, dan mendukung kerja sama antaranggota tim.

Git merupakan salah satu sistem Version Control terdistribusi yang menyediakan mekanisme untuk mengelola repository, staging area, commit, branch, merge, dan sinkronisasi dengan remote repository. GitHub dapat digunakan sebagai salah satu remote repository untuk menyimpan proyek secara daring dan mendukung kolaborasi.

Alur dasar yang perlu dipahami adalah Working Directory → Staging Area → Commit → Remote Repository. Dengan memahami alur tersebut serta mempraktikkan perintah dasar seperti git status, git add, git commit, git branch, git push, dan git pull, pengguna dapat mulai menerapkan Version Control secara terstruktur dalam pengembangan proyek.
